# 会话 Git 审阅

`extensions/diff` 保留原 `/diff`，新增 `/changes` 和对话编辑器 **Ctrl+R**：查看当前会话影响的 Git 文件，逐文件确认完成，避免重复审阅。

## 使用

1. 让当前会话编辑文件，或通过 Shell、`task_bash`、`async_bash`、fork Agent、teammate 执行修改。
2. 在对话编辑器按 **Ctrl+R**，或执行 `/changes`。
3. 选择文件查看完整 Git diff：新增行用明确的绿色背景、删除行用明确的红色背景，铺满差异栏，折行后延续相同背景（不依赖主题的中性工具背景，适配深浅主题）；检查后按 **d（确认完成）**，文件立即从待审列表隐藏。
4. 文件再次发生变化后重新待审，仍显示相对 HEAD 的完整差异，不是相对上次确认的增量。

| 按键 | 操作 |
|---|---|
| j / k、↓ / ↑ | 当前区域向下/上移动，支持 `5j` 等次数前缀 |
| h / l | 返回文件列表 / 查看差异 |
| gg / G | 当前区域首尾；`10gg` / `10G` 跳到第 10 项或第 10 个显示行 |
| Ctrl+u / Ctrl+d | 当前区域上/下半页（不会确认文件） |
| Ctrl+b / Ctrl+f | 当前区域上/下一页 |
| Enter | 查看所选文件 |
| Tab | 切换列表/详情焦点 |
| PageUp / PageDown | 宽屏滚动详情；窄屏翻动当前区域 |
| r | 刷新 |
| d | 确认当前所见版本完成 |
| Escape | 先取消未完成的次数/`g` 前缀；否则宽屏退出，窄屏从详情返回列表，再按退出 |
| q / Ctrl+C | 关闭面板 |

Vim 按键仅用于只读导航，不提供插入模式、删除或 Vim 命令行。单独 `d` 仍是确认完成，次数前缀不适用于确认；不支持的 `g` 组合会取消，不会把 `gd` 当成确认。

面板使用全屏覆盖层：宽终端左右分栏，小于 90 列切换单栏。模型流式输出期间也可打开和操作；普通终端模式暂时移开聊天显示组件，避免增长的聊天布局推动面板反复重绘。模型和后台任务继续运行、消息照常记录，关闭后恢复最新聊天内容，不清除输入草稿。确认全部文件后保留“当前没有待审文件”空态，方便观察后台任务。

**确认只保存审阅元数据，不写代码、不执行 git add/commit/restore，不触发模型回合。** 二进制或截断预览也可以确认，但其含义是确认当前完整文件版本，请自行核查未显示内容。单文件预览上限为 1 MiB 或 10,000 行，指纹仍覆盖完整内容。

## 快捷键兼容

- Ctrl+R 仅通过 Pi 的对话编辑器扩展快捷键入口接入；`/resume` 选择器内仍是原有重命名操作，其他选择器保留其按键语义。
- Pi 0.84.3 可能提示与 `app.session.rename` 的非保留快捷键重用警告，并明确使用扩展；这不是编辑器拒绝注册。无需删除重命名配置。
- 改绑：`pi --changes-key alt+v`；禁用快捷键但保留命令：`pi --changes-key=''`。
- 如果你已让 input-history 或其他扩展占用 Ctrl+R，选择一个不同的 `--changes-key`。Pi 对真正编辑器级保留键的冲突仍会拒绝注册，可始终使用 `/changes`。
- 本功能不修改 `~/.pi/agent/keybindings.json`。非 TUI（RPC/JSON/print）不支持自定义终端面板。

## 文件范围与差异基准

- 仅当前 cwd 所属的 Git 工作树（从子目录启动也按仓库相对路径展示），不聚合子任务在其他仓库/独立 worktree 的修改，也不遍历 submodule、嵌套仓库或忽略文件。
- 会话开始前已有的脏文件不自动进入列表。若本会话进一步改变它，才纳入，并标注可能包含会话前的改动。
- write/edit 和兼容路径工具只核对显式目标；Shell 和子 Agent 使用执行窗口内的工作树快照。任务工具返回后仍继续跟踪后台执行；teammate idle 不算活动窗口。
- **Git 不能准确鉴定作者。** 在 Shell/Agent 执行窗口内同时进行的外部编辑可能一起纳入；窗口外陌生文件的外部编辑不自动纳入。已纳入的文件无论由谁再次修改，确认都会失效。
- 仅靠轮询无法发现两次采样之间修改后又完全恢复的瞬时变化。
- tracked 文件默认显示 HEAD 到工作树的净差异，综合暂存和未暂存的效果。若工作树恰好等于 HEAD、index 却有变化，分开展示暂存与未暂存，避免漏审。
- 未跟踪文件按新增展示；没有首个提交的仓库使用空树语义。新增、删除、rename、模式变化、合并冲突和二进制状态均会明确呈现。
- 提交或还原后已无差异的候选自动隐藏，但会话归属保留，后续修改仍可显示。

## 确认、持久化与刷新

确认记录绑定完整内容、存在性、模式、路径、HEAD 文件基准和 index 版本，不依赖文件时间戳/大小。因此等长修改也会重新待审；无关文件的提交不会单独让确认失效。

详情读取前后检查版本，确认前再次核对。若你看到 V1 时文件已变为 V2，将提示重新检查，而不会将 V2 标为完成。

元数据通过 session 自定义条目保存，仅含路径、哈希及归属/确认状态，不含文件正文或 diff，不进入模型上下文：

- 恢复同一会话：恢复确认并重新核对磁盘版本。
- `/new`：建立新基线，不继承另一会话的待审列表。
- tree/fork：仅重放目标活动分支可见的记录，不继承废弃分支确认，也不回滚磁盘文件。
- 旧会话没有审阅记录：提示“从启用跟踪起记录”，不猜测历史修改来源。

活动任务期间约每秒扫描一次；面板打开但无活动任务时约每两秒核对候选。打开、手动刷新和任务结束也会刷新。查询串行合并，不启动重叠的全仓扫描。

## 故障处理

- 无 Git 仓库时显示明确原因，不展示假空列表。
- Git 查询失败或超时保留最后成功状态但标为过期，禁止用不确定版本确认；按 `r` 重试。已有基线的操作若前置扫描失败，其归属窗口仍保留到成功补扫。
- 初次基线尚未成功建立时，明确带写入语义的工具会返回说明，避免修改完全不可追踪；通过 `/changes` 重试恢复。非 Git 目录不因此禁止工具使用。
- 确认持久化失败则保持待审并报错，不提示完成。候选保存失败也会显示未保存并在刷新时重试。
- 没有 tasks 扩展时明确显示后台跟踪不可用；直接 write/edit 和前台操作仍可跟踪。
- 会话切换、reload 或退出会取消旧查询、关闭面板、清理订阅及计时器；晚到结果不污染新会话。
